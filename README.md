# Мониторинг фор NBA (Marathonbet)

Расписание точное — **одна проверка каждые 30 минут** (в интервалах :00–:29
и :30–:59 мск): GitHub Actions запускает проверку каждые 5 минут, а скрипт
`marathon_fora_monitor.py` сам отслеживает, была ли уже проверка в текущем
получасовом интервале, — поэтому задержки и пропуски слотов GitHub на
результат не влияют. Скрипт открывает страницу
`https://www.marathonbet.ru/su/betting/Basketball/NBA`, считывает главную фору
(гандикап) и коэффициенты по каждой игре, сравнивает с прошлой проверкой и
**построчно записывает по каждой игре, изменилась линия или нет**.
Изменением считается только сдвиг форы (гандикапа): движения коэффициентов
записываются в таблицу, но игру «изменённой» не помечают.
Результаты сохраняются обратно в этот репозиторий.

## Где смотреть результаты

| Файл | Что внутри |
|---|---|
| `data/log.txt` | Читаемый журнал: строка на каждую игру при каждом запуске — «НОВЫЙ МАТЧ / БЕЗ ИЗМЕНЕНИЙ / ИЗМЕНЕНИЕ» с расшифровкой «было → стало» |
| `data/history.csv` | Полная история построчно, разделитель `;` (открывается в Excel) |
| `data/report.txt` | Отчёт по каждой игре: все проверки от появления в линии до начала матча; у каждого матча своя шапка (номер, время начала, число проверок и сдвигов), строки вида «05 ноя 03:00 [+4.5 (1.80) / -4.5 (2.00)]»; 🔴 помечает строки, где фора сдвинулась |
| `data/report.html` | Тот же отчёт с подсветкой: строки со сдвигом форы выделены красным целиком. Скачайте файл и откройте в браузере |
| `data/изменения/` | Архив по игровым дням: за каждый день, где фора сдвигалась, появляется файл `ГГГГ-ММ-ДД.txt` — только игры со сдвигами, все их проверки от появления в линии до начала матча, а после завершения матча — строка «✅ Итоговый счёт: X:Y» (с пометкой «(овертайм)», если овертайм был) |
| `data/results.json` | Кэш итоговых счётов завершившихся матчей (источник — публичный API ESPN) |
| `data/report/` | Полные отчёты по игровым дням: файлы `5.11.txt`, `6.11.txt`, … (день.месяц) — **все** игры этого дня и все их проверки от появления в линии до закрытия линии (начала матча), 🔴 помечает сдвиги форы |
| `data/state.json` | Служебный файл: последний снимок линий для сравнения |
| Вкладка **Actions** | Каждая проверка — отдельный запуск: видно статус (зелёный/красный) и время |

Пример строки журнала при изменении:

```
05 ноя 03:00 | Вашингтон Уизардс - Атланта Хокс: было [+4.5/-4.5] → стало [+3.5/-3.5]; фора 1: +4.5 → +3.5
```

Так выглядят отчёты (фрагмент `data/report.txt`; в `data/изменения/` и
`data/report/` оформление то же, плюс строка «✅ Итоговый счёт»):

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  NBA · ДИНАМИКА ФОРЫ — MARATHONBET
  Обновлён: 05.11.2026 19:13 МСК · время проверок московское
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
────────────────────────────────────────────────────────────────────
1. ВАШИНГТОН УИЗАРДС – АТЛАНТА ХОКС
   начало 05 ноя 03:00 · проверок: 4 · сдвигов форы: 1
    04 ноя 23:57   [+3.5 (1.83) / -3.5 (1.98)]
    05 ноя 00:11   [+3.5 (1.83) / -3.5 (1.98)]
🔴  05 ноя 02:36   [+1.5 (1.97) / -1.5 (1.83)]
```

**Схлопывание пустых серий**: если фора не менялась 2 часа и дольше,
промежуточные проверки «без изменений» убираются из отчёта — остаётся
последнее изменение и одна строка вместо десятков одинаковых:

```
    05 ноя 08:53   [-5.5 (1.95) / +5.5 (1.85)]
🔴  05 ноя 10:00   [-7.5 (1.97) / +7.5 (1.83)]
    ··· далее 8 проверок без изменений (последняя 05 ноя 18:32) ···
```

Серии короче 2 часов показываются целиком; число в шапке матча
(«проверок: N») всегда показывает полный объём проверок.

## Как развернуть (5 минут, без программирования)

1. Зарегистрируйтесь на https://github.com (если аккаунта нет).
2. Нажмите **+** в правом верхнем углу → **New repository**.
3. Имя, например `nba-fora-monitor`. Выберите **Public** — для публичных
   репозиториев Actions бесплатны без лимита минут. Нажмите **Create repository**.
4. На открывшейся странице нажмите ссылку **uploading an existing file**.
   Перетащите в окно **содержимое папки** из этого набора (файлы скрипта, README
   и папку `data` с файлами). Дождитесь загрузки и нажмите **Commit changes**.
5. Теперь добавьте сам робота: в репозитории **Add file → Create new file**,
   в поле имени файла введите `.github/workflows/monitor.yml`
   (GitHub сам создаст папки) и вставьте содержимое файла `monitor.yml`
   из этого набора. Нажмите **Commit changes**.
6. Проверка: вкладка **Actions** → слева «Мониторинг фор NBA» → справа кнопка
   **Run workflow → Run workflow** — это ручной тестовый запуск. Через минуту
   появится зелёная галочка, а в папке `data` обновятся файлы.

Дальше всё работает само: проверка каждые 30 минут, новые данные — новые
коммиты в репозиторий.

## Нюансы GitHub Actions

- **Точность расписания**: расписание GitHub срабатывает с задержкой в
  несколько минут, а при пиковых нагрузках отдельные запуски пропускают
  (бывали пропуски сразу двух слотов :00 и :30 подряд). Поэтому workflow
  запускается каждые 5 минут (`*/5 * * * *`), а скрипт делает полноценную
  проверку только если в текущем получасовом интервале её ещё не было
  (метка хранится в `data/state.json`). Итог: проверка раз в 30 минут,
  а разовый сбой сайта перепроверяется уже через 5 минут.
- Ручной запуск (**Run workflow**) всегда проверяет линию немедленно.
- **60 дней**: если в репозитории нет активности 60 дней, GitHub отключает
  расписание. Здесь это не грозит — робот коммитит сам каждые 30 минут.
- **Приватный репозиторий**: тоже можно, но бесплатный лимит 2000 минут/мес;
  при запусках каждые 5 минут частые пропуски-запуски съедают минуты —
  публичный репозиторий надёжнее (Actions бесплатны без лимита).
- Если Marathonbet заблокирует запросы с серверов GitHub, в `data/log.txt`
  появится строка `[!] ... ОШИБКА`, а запуск станет красным — при этом уже
  через 5 минут будет следующая попытка, так что данные не теряются.
- Файл `data/log.txt` растёт постоянно; раз в месяц-другой можно подрезать
  старое (открыть файл → значок карандаша Edit → удалить лишнее → Commit changes).

## Локальный запуск (не обязательно)

Скрипту нужен только Python 3.8+:

```bash
python3 marathon_fora_monitor.py --once                # одна проверка (раз в полчаса)
python3 marathon_fora_monitor.py --once --force        # проверка немедленно
python3 marathon_fora_monitor.py --loop                # вечный цикл: проверка каждые 30 мин
python3 marathon_fora_monitor.py --loop --interval 600 # пробуждение каждые 10 мин,
                                                       # проверка всё равно раз в полчаса
```
